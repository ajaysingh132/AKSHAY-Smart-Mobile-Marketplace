## मार्केटप्लेस की चार शाखाएँ
मुख्य होमपेज से `marketplace/` खोलें: `marketplace/index.html` में (1) होलसेल मार्केटप्लेस, (2) फुटकर मार्केट, (3) एडमिन पैनल, और (4) होलसेल व्यापारी पंजीकरण बोर्ड शामिल हैं। शुरुआती सप्लायर/ग्राहक/उत्पाद डेमो रिकॉर्ड हैं; एडमिन पैनल से संपादन, नए रिकॉर्ड, आवेदन सूची, JSON बैकअप/आयात उपलब्ध हैं। ये रिकॉर्ड इसी ब्राउज़र के `localStorage` में सेव होते हैं—किसी दूसरे मोबाइल या ब्राउज़र से अपने-आप सिंक नहीं होंगे। वास्तविक डेटा भरने से पहले बैकअप रखें। एडमिन पैनल अभी authentication से सुरक्षित नहीं है; सार्वजनिक उत्पादन उपयोग से पहले लॉगिन, सर्वर डेटाबेस और access control जोड़ें।

## वर्तमान MVP (स्थानीय / ऑफलाइन प्रोटोटाइप)
फ़ाइल: `ai-manager/index.html`

- डैशबोर्ड: आज की बिक्री, नकद/UPI/बकाया, खर्च, अनुमानित सकल लाभ, मासिक बिक्री, स्टॉक मूल्य और पार्टी बकाया
- उत्पाद रजिस्टर: स्वतः Product ID, स्टॉक, लागत, फुटकर/होलसेल मूल्य और कम-स्टॉक सीमा
- बिक्री/बिल: नकद, UPI, उधार/आंशिक भुगतान; स्टॉक घटता है; बिल प्रिंट/PDF
- खरीद: स्टॉक बढ़ता है; भारित औसत लागत का अनुमान; सप्लायर बकाया
- ग्राहक/सप्लायर रजिस्टर तथा वसूली/भुगतान
- दैनिक आय-व्यय
- अवधि आधारित रिपोर्ट; CSV जो Excel में खुल सकता है; JSON बैकअप/आयात
- रिकॉर्ड-आधारित नियम-सहायता (यह अभी बाहरी LLM से जुड़ा AI नहीं है)
- ऑडिट ट्रेल का स्थानीय रिकॉर्ड; वित्तीय रिकॉर्ड मिटाने का UI नहीं
- इंटरनेट के बिना ब्राउज़र localStorage में रिकॉर्ड दर्ज हो सकते हैं

## महत्वपूर्ण सीमाएँ
यह **स्थानीय MVP** है, अभी उत्पादन-तैयार या क्लाउड-सिंक सिस्टम नहीं:
1. डेटा केवल इसी ब्राउज़र/डिवाइस में है; बैकअप लेकर सुरक्षित स्थान पर रखें।
2. लॉगिन, बहु-डिवाइस सिंक, सर्वर-साइड ऑडिट, उपयोगकर्ता भूमिकाएँ और क्लाउड बैकअप अभी नहीं हैं।
3. खरीद/बिक्री अभी एक रिकॉर्ड में एक उत्पाद लाइन दर्ज करती है; multi-line invoice और return/void reversal अगला चरण है।
4. UPI/बैंक भुगतान स्वतः सत्यापित नहीं होते।
5. GST रिपोर्टिंग/टैक्स रिटर्न नहीं बनते। GST दर और इनवॉइस नियम लागू पंजीकरण/कानून के अनुसार सत्यापित हों।
6. स्थानीय ऑडिट ट्रेल सुरक्षित, अपरिवर्तनीय server audit log का विकल्प नहीं है।
7. सलाहकार केवल स्थानीय रिकॉर्ड पर नियम-आधारित उत्तर देता है; AI API अभी नहीं जुड़ी है।

## सुपाबेस स्कीमा
`ai-manager/supabase-schema.sql` एक प्रारंभिक schema draft है। अभी किसी Supabase project पर लागू नहीं किया गया है। सही project/account चुनने और सुरक्षित owner login तय होने के बाद ही लागू करें। इसमें owner-scoped RLS और financial records के लिए DELETE policy नहीं है। Production से पहले atomic stock posting, parent/child shop consistency, immutable audit log, backups और security review अनिवार्य हैं।

## GitHub Pages पर खोलना
Repository की Settings → Pages में publishing enabled होने पर `ai-manager/index.html` इस path पर उपलब्ध हो सकता है:
`https://<github-username>.github.io/<repository-name>/ai-manager/`
यह URL तभी काम करेगा जब GitHub Pages सक्रिय हो।

## सुरक्षित अगले चरण
1. एक समर्पित Supabase project चुनें/सक्रिय करें।

6. GST, billing, backup/restore और permissions की वास्तविक दुकान के नमूना डेटा से जाँच करें।
